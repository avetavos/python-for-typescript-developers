## การเปรียบเทียบ toolchain

ก่อนลงมือเขียนโค้ด ควรเห็นภาพก่อนว่า toolchain ของ Python เทียบกับฝั่ง Node ตัวไหนเป็นตัวไหน:

export const toolchainTs = `# Node / TypeScript toolchain
node       → runtime (executes JS)

npx        → run a package binary without installing globally
tsc        → TypeScript compiler
package.json → project manifest
node_modules/ → installed dependencies (per project)`;

export const toolchainPy = `# Python toolchain
python3    → runtime (executes Python)
pip        → package manager (installs packages)
uv         → installs Python itself + deps (closest to npm)
pipx       → run a tool without polluting your env
mypy/pyright → optional type checker (like tsc)
pyproject.toml → project manifest (modern)
venv/      → isolated dependency folder (per project)`;

## ติดตั้ง Python

**ทุก OS** (แนะนำ — ใช้ `uv` ซึ่งติดตั้งตัว Python ให้ด้วย):
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.14
uv run python --version   # Python 3.14.x
```

`uv` คือสิ่งที่ใกล้เคียง npm ที่สุดเท่าที่ Python มี — เครื่องมือเดียวจัดการทั้ง interpreter, virtual environment และ dependency ส่วนที่เหลือของบทนี้ยังแสดงท่าคลาสสิก `venv` + `pip` ซึ่งคุณจะยังเจอในโปรเจกต์เดิมส่วนใหญ่

**macOS** (แบบคลาสสิก — Homebrew):
```bash
brew install python@3.14
python3 --version   # Python 3.14.x
pip3 --version
```

**Windows** (แนะนำ — ใช้ installer อย่างเป็นทางการ):
1. ดาวน์โหลดจาก [python.org/downloads](https://python.org/downloads)
2. เช็ค "Add python.exe to PATH" ระหว่างการติดตั้ง
3. เปิดเทอร์มินัลใหม่: `python --version`

**Linux (Ubuntu/Debian)**:
```bash
sudo apt update && sudo apt install python3 python3-pip python3-venv
python3 --version
```

## Virtual environments — venv เทียบเท่ากับ node_modules

ใน Node คำสั่ง `npm install` สร้าง `node_modules/` ไว้ในโปรเจกต์ ทำให้แต่ละโปรเจกต์มี dependency ชุดของตัวเอง ฝั่ง Python ตัวที่ทำหน้าที่เดียวกันคือ **virtual environment** (`venv`) ที่เป็นไดเรกทอรีแยกที่เก็บทั้ง Python interpreter และ package ไว้ในนั้น

ถ้าไม่ใช้ venv คำสั่ง `pip install` จะลง package ระดับ global แล้วโปรเจกต์ต่าง ๆ จะชนกันเอง ดังนั้นใช้ venv เสมอ

export const venvTs = `# Node: project isolation is automatic
mkdir my-project && cd my-project
npm init -y
npm install express       # goes into ./node_modules
# no extra setup needed`;

export const venvPy = `# Python: you must explicitly create isolation
mkdir my-project && cd my-project
python3 -m venv venv      # creates ./venv directory
source venv/bin/activate  # macOS/Linux
# venv\\Scripts\\activate   # Windows PowerShell

pip install fastapi        # installs into ./venv, not globally
python3 script.py`;

<TsGo ts={venvTs} go={venvPy} />

พอรัน `source venv/bin/activate` แล้ว prompt จะขึ้น `(venv)` ให้เห็น จากจุดนี้ `python` และ `pip` จะชี้ไปที่ venv ของโปรเจกต์ ถ้าจะออกก็สั่ง `deactivate`

<PyOnly title="ทำไม Python ถึงต้องมีขั้นตอน activate ที่ชัดเจน?">

Node resolve package ด้วยการไล่ขึ้นไปตาม directory tree เพื่อหา `node_modules/` แต่ Python ไม่ทำแบบนั้น เพราะมองหาแค่ใน Python installation ที่ active อยู่เท่านั้น สคริปต์ `activate` จึงมีหน้าที่เซ็ต environment variable (`PATH`, `VIRTUAL_ENV`) ให้คำสั่ง `python` กับ `pip` resolve ไปที่ชุดใน venv แทนชุดของ system

ถ้าอยากได้ความรู้สึกอัตโนมัติแบบ Node ก็มี tool อย่าง `direnv` หรือ `pyenv-virtualenv` ที่ activate venv ให้เองทันทีที่คุณ `cd` เข้าไปในโฟลเดอร์โปรเจกต์

</PyOnly>

## การติดตั้งและบันทึก dependencies

export const depsTs = `# Node
npm install express              # install + save to package.json
npm install --save-dev jest      # devDependency
npm install                      # install from package.json
npm ci                           # clean install from package-lock.json`;

export const depsPy = `# Python (classic workflow)
pip install fastapi               # installs but does NOT save
pip freeze > requirements.txt     # snapshot current env
pip install -r requirements.txt   # install from snapshot

# Modern workflow with pyproject.toml
pip install .                     # install project deps from pyproject.toml`;

<TsGo ts={depsTs} go={depsPy} />

<PyOnly title="pip freeze vs package.json — ความแตกต่างสำคัญ">

`npm install express` จะเติม `"express"` ลงใน `package.json` ให้อัตโนมัติ ส่วน `pip install fastapi` ไม่แก้ไฟล์ไหนเลย แค่ก๊อป bytes ลง `venv/` เท่านั้น ถ้าอยากบันทึกสภาพ environment ปัจจุบันคุณต้องสั่ง `pip freeze > requirements.txt` เอง

ทางออกของ Python ยุคใหม่คือ `pyproject.toml` คู่กับ tool อย่าง `hatch`, `poetry` หรือ `uv` ซึ่งทำงานใกล้เคียง npm มากขึ้น เช่น `poetry add fastapi` เพิ่ม dependency พร้อมอัปเดต `pyproject.toml` ให้ในขั้นตอนเดียว เรื่อง `pyproject.toml` จะลงรายละเอียดในบทเรียน Project Anatomy

</PyOnly>

## ตัวอย่าง workflow ฉบับสมบูรณ์

นี่คือลำดับขั้นตอน "เริ่มโปรเจกต์ Python ใหม่" แบบเต็ม วางเทียบกับสิ่งที่คุณทำตอนเริ่มโปรเจกต์ Node:

export const workflowTs = `# Node project setup
mkdir api && cd api
npm init -y
npm install express typescript ts-node @types/node
npx tsc --init
# edit tsconfig.json...
npm run dev`;

export const workflowPy = `# Python project setup
mkdir api && cd api
python3 -m venv venv
source venv/bin/activate   # activate venv
pip install fastapi uvicorn

# Run the app
uvicorn main:app --reload

# Capture deps for teammates
pip freeze > requirements.txt`;
